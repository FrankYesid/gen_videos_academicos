AI COURSE VIDEO GENERATOR
ESPECIFICACION MAESTRA DEL PROYECTO

============================================================
1. DESCRIPCION DEL PROYECTO
============================================================

Construir una plataforma Full Stack denominada:

AI Course Video Generator

Objetivo:

Permitir que un usuario cargue un archivo PDF con contenido academico y que el sistema transforme automaticamente ese contenido en una clase educativa en video utilizando Inteligencia Artificial.

Flujo principal:

PDF
-> Extraccion de contenido
-> Analisis del contenido
-> Identificacion del tema
-> Diseno pedagogico
-> Generacion del guion
-> Validacion del guion
-> Generacion del video
-> Integracion con HeyGen
-> Seguimiento del procesamiento
-> Webhook
-> Control de calidad
-> Video final

La aplicacion debe estar documentada, probada y preparada para ejecutarse localmente mediante Docker.


============================================================
2. OBJETIVO GENERAL
============================================================

La plataforma debe permitir:

1. Subir un archivo PDF.
2. Validar que el archivo sea valido.
3. Extraer el contenido del PDF.
4. Identificar automaticamente:
   - titulo
   - tema
   - subtemas
   - conceptos principales
   - conceptos secundarios
   - objetivos de aprendizaje
   - nivel de dificultad
   - requisitos previos
   - idioma
5. Disenar una estructura pedagogica.
6. Generar un guion educativo.
7. Dividir el contenido en escenas.
8. Mostrar el guion antes de generar el video.
9. Permitir al usuario aprobar el guion.
10. Generar el video mediante HeyGen.
11. Recibir actualizaciones mediante webhook.
12. Mostrar el progreso al usuario.
13. Ejecutar un proceso de QA.
14. Guardar el video final.
15. Mostrar el video en el frontend.
16. Mantener un historial de cursos generados.
17. Registrar las ejecuciones de cada agente.
18. Disponer de pruebas unitarias.
19. Disponer de pruebas de integracion.
20. Disponer de pruebas End-to-End.
21. Disponer de documentacion completa.


============================================================
3. PRINCIPIOS DE DESARROLLO
============================================================

El proyecto debe seguir estos principios:

- Codigo limpio.
- Arquitectura modular.
- Separacion de responsabilidades.
- Tipado fuerte.
- Validacion de datos.
- Manejo explicito de errores.
- Logs estructurados.
- Variables de entorno.
- Nunca almacenar API keys en el frontend.
- Nunca colocar secretos directamente en el codigo.
- Codigo testeable.
- Codigo documentado.
- API versionada.
- Servicios externos desacoplados.
- Uso de interfaces cuando sea apropiado.
- Dependencias minimas.
- Evitar codigo duplicado.
- No utilizar codigo ficticio para simular integraciones reales salvo en modo MOCK.
- Todas las integraciones externas deben disponer de un modo MOCK para pruebas.

============================================================
8. SUBIDA Y PROCESAMIENTO DEL PDF
============================================================

El frontend debe permitir:

- Drag & Drop.
- Seleccion manual.
- Mostrar nombre.
- Mostrar tamano.
- Validar extension.
- Validar MIME type.
- Mostrar progreso.
- Mostrar errores.

Inicialmente aceptar:

application/pdf

Limite configurable:

MAX_FILE_SIZE_MB=50

Endpoint:

POST /api/v1/documents

Utilizar multipart/form-data.

Proceso:

1. Validar archivo.
2. Generar hash SHA-256.
3. Guardar archivo.
4. Registrar documento en PostgreSQL.
5. Extraer texto.
6. Registrar numero de paginas.
7. Guardar texto extraido.
8. Crear Course.
9. Iniciar workflow.

Utilizar una libreria como PyMuPDF.

Si el PDF no contiene texto:

- Detectar ausencia de texto.
- Informar al usuario.
- Preparar arquitectura para OCR futuro.

No implementar OCR complejo en el MVP salvo que sea necesario.

============================================================
11. SCRIPT AGENT
============================================================

Archivo:

backend/app/agents/script_agent.py

Responsabilidad:

Convertir la estructura pedagogica en un guion audiovisual.

Cada escena debe tener:

{
  "id": 1,
  "title": "Introduccion",
  "duration_seconds": 45,
  "narration": "...",
  "visual_instruction": "...",
  "on_screen_text": "...",
  "educational_purpose": "..."
}

El guion debe contener:

1. Introduccion.
2. Objetivos.
3. Desarrollo.
4. Ejemplos.
5. Aplicacion.
6. Resumen.
7. Cierre.

Evitar:

- Texto excesivamente largo en pantalla.
- Informacion no respaldada por el PDF.
- Conceptos inventados.
- Datos no verificables.
- Escenas sin proposito pedagogico.

============================================================
15. ESTRATEGIAS DE VIDEO
============================================================

El sistema debe soportar dos estrategias.

ESTRATEGIA A: HEYGEN VIDEO AGENT

Ventajas:

- Mayor automatizacion.
- Menor trabajo inicial.
- Generacion desde una descripcion/prompt.

ESTRATEGIA B: HEYGEN TEMPLATE API

Ventajas:

- Mayor control.
- Consistencia visual.
- Control de escenas.
- Ideal para cursos completos.

Crear una abstraccion:

VideoProvider

Implementaciones:

HeyGenVideoAgentProvider
HeyGenTemplateProvider
MockVideoProvider

El sistema no debe quedar acoplado a una sola estrategia.


============================================================
16. MODO MOCK
============================================================

Variable:

HEYGEN_MODE=mock

Cuando este activa:

- No realizar llamadas reales a HeyGen.
- Utilizar MockVideoProvider.
- Simular created.
- Simular processing.
- Simular completed.
- Devolver un recurso de prueba.

Produccion:

HEYGEN_MODE=production
